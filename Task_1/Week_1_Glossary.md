# Glossary Contributions

## Continuous Integration (CI)

**Definition**
Continuous Integration is a software engineering practice where developers frequently merge their changes into a central repository, triggering an automated process to build the game and run tests. In game development, this practice is crucial for catching integration errors early and ensuring that newly committed code or assets do not break the playable state of the game.

**Citations**
- Duvall, P. M., Matyas, S., & Glover, A. (2007). *Continuous integration: improving software quality and reducing risk*. Pearson Education.
- Fowler, M. (2006). *Continuous Integration*. ThoughtWorks. https://martinfowler.com/articles/continuousIntegration.html

## Production Pipeline

**Definition**
A production pipeline is the structured sequence of established processes, workflows, and tools designed to systematically create, process, and import digital assets into a game engine. It serves as the organizational backbone of a project, ensuring that collaborative efforts between artists, designers, and programmers efficiently converge from initial creation through to final implementation without workflow bottlenecks.

**Citations**
- Gregory, J. (2018). *Game Engine Architecture* (3rd ed.). CRC Press. (Chapter 14: The Tool Pipeline and OS).
- Ramadan, R., & Widyani, Y. (2013). Game development life cycle guidelines. *2013 International Conference on Advanced Computer Science and Information Systems (ICACSIS)*, 95-100.

## Version Control System (VCS)

**Definition**
A Version Control System is an essential software tool used to track, manage, and historically log modifications to source code and digital assets, facilitating simultaneous collaboration across multidisciplinary development teams. It safeguards a project from critical data loss by resolving file conflicts and allowing developers to reliably revert back to previously stable versions if a game-breaking bug is introduced.

**Citations**
- Spinellis, D. (2005). Version control systems. *IEEE Software*, 22(5), 108-109.
- Chacon, S., & Straub, B. (2014). *Pro Git* (2nd ed.). Apress.
